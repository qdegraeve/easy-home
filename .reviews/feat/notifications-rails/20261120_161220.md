## Intention

Résumé du matin en notification push (ADR 0012) : réglages par utilisateur (activé, heure, foyers), téléphones
rattachés à la session, envoi récurrent toutes les 5 minutes, une fois par jour au plus, rien sans tâche ; bouton de
notification de test.

## Revue

Deux unités relues en parallèle : envoi (services, requête, modèles, migration, job, gem) ; pages, contrôleurs,
policies, formulaire, vues, locales.

Points vérifiés et écartés :
- un seul résumé par jour : réservation atomique du jour avant l'envoi ;
- foyers : invité, non suivi et autre foyer exclus ; tâches inactives (plante archivée) exclues ; ordre déterministe ;
- `DueOccurrencesQuery` : mêmes résultats que l'ancienne requête de l'accueil ;
- fuseau : `Time.current` en heure de La Réunion, sans heure d'été ; changement de jour testé ;
- téléphones : `has_many through` des sessions vers un propriétaire polymorphe ; déconnexion = appareil supprimé ;
  `upsert` par jeton avec horodatage ; appareil supprimé avant l'envoi : job abandonné par la gem ;
- accès : réglages et notification de test limités à l'utilisateur ; notification de test seulement vers ses
  téléphones ; enregistrement dans la session courante ;
- migration : valeurs par défaut valides pour les lignes existantes, index unique sur une table neuve.

## Findings

### 1. Un résumé « du matin » pouvait partir le soir
- **Fichier** : `app/services/notifications/send_digests.rb`
- **Sévérité** : moyenne (produit)
- **Constat** : aucune borne haute sur l'heure : un premier téléphone enregistré à 21 h, un résumé activé l'après-midi
  ou une panne finie à 18 h déclenchaient le résumé immédiatement.
- **Correction** : retard maximal de 2 heures (`LATENESS`), spec et ADR.
- **Statut** : corrigé

### 2. Réglage sans l'interrupteur : erreur 500
- **Fichier** : `app/forms/notification_settings_form.rb`
- **Sévérité** : moyenne
- **Constat** : une requête sans `digest_enabled` passait la validation puis échouait en base (colonne non nulle).
- **Correction** : validation booléenne ; spec (422).
- **Statut** : corrigé

### 3. Specs manquantes
- **Constat** : tâche sans sujet, corps tronqué, foyer unique (case masquée, foyer gardé).
- **Correction** : specs ajoutées.
- **Statut** : corrigé

## Écartés ou acceptés

- Jeton Firebase d'un autre téléphone : qui le connaît peut rattacher ce téléphone à son compte (il ne lit rien) ;
  contrepartie notée dans l'ADR.
- Échec d'envoi après la réservation du jour : ce résumé est perdu pour la journée (accepté, ADR).
- Heure invalide bricolée non conservée dans le menu après erreur : impossible depuis le formulaire.
- Sans credentials Firebase, l'envoi échoue dans le job (signalé), sans erreur de page.
