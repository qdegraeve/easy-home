## Vue d'ensemble

Le commit de correction verrouille la tâche (et la plante) dans chaque service qui écrit, rend le dernier arrosage
facultatif, limite une tâche à une réalisation par jour, permet d'annuler une réalisation depuis le journal et remplace
`window.confirm` (bloqué dans certaines webviews) par une confirmation dans la page. Les refus d'accès sont testés sur
chaque écriture. Revue menée en deux unités (services et modèles ; contrôleurs, vues et JS).

## Conclusions

### [medium] Messages d'échec des contrôleurs jamais exercés, annulation sur une plante archivée non testée

**Fichier**: `app/controllers/task_occurrences/completions_controller.rb:11`
**Problème**: les branches `t(".#{result.failure.first}")` (`inactive`, `already_done_today`), `t(".not_done")` et la clé
`.already` de `Plants::ArchivesController` ne sont parcourues par aucune request spec : une faute de clé passerait
inaperçue. L'annulation d'un arrosage sur une plante archivée n'est testée nulle part, et elle affiche « prochaine
échéance recalculée » alors qu'aucune échéance n'est recréée.
**Impact**: message « translation missing » possible en production, message trompeur sur une plante archivée.
**Suggestion**: une request spec par branche d'échec ; sur une tâche arrêtée, un message sans « prochaine échéance ».
**Statut**: corrigé (describe « messages d'échec » dans `spec/requests/plants_spec.rb`, message « Arrosage annulé. » sur une
tâche arrêtée).
